# Task `ios-keyboard-missing` (owner: codex)

**Bug:** on a real iPhone (iOS 26.6.1), the TestFlight build 1.0 (1) of TrustChain Keyboard installs and the container app opens. But the keyboard **never appears** in Settings → General → Keyboard → Keyboards → Add New Keyboard: there's no "Third-Party Keyboards" section at all, even after a restart. The app's own Settings page shows only Siri, Search and Mobile Data.

**Evidence collected so far:**
- The archive contains `TrustChainKeyboard.app/PlugIns/Keyboard.appex`, and it was validated by Xcode.
- Signing (codesign of the archive): both the app and the appex are signed "Apple Distribution". Their App Store profiles match: the entitlement `application-identifier` is TEAM.mn.trustchain.keyboard / TEAM.mn.trustchain.keyboard.ext, `beta-reports-active` is true and `get-task-allow` is false. `codesign --verify --deep --strict` says valid.
- The extension's Info.plist (simulator build) has CFBundlePackageType XPC!, NSExtensionPointIdentifier com.apple.keyboard-service, NSExtensionPrincipalClass Keyboard.KeyboardViewController, NSExtensionAttributes {IsASCIICapable false, PrefersRightToLeft false, PrimaryLanguage "mn", RequestsOpenAccess false}, MinimumOSVersion 15.0 and UIDeviceFamily [1,2].
- In the **iOS 26.5 simulator**, `pluginkit -mAvvv -p com.apple.keyboard-service` lists mn.trustchain.keyboard.ext as "TrustChain Keyboard". It wasn't checked whether the simulator's Settings shows it.
- The project is generated by XcodeGen from `ios/project.yml` and built by `.github/workflows/ios.yml` (Release, manual signing, Xcode 26.6, iOS 26.5 SDK).

**Your job:** find the most likely root causes for "keyboard extension installed on a device but not offered in Add New Keyboard", by reading `ios/project.yml`, `ios/Keyboard/*`, `ios/App/*` and the workflow. Consider every known cause:
- Info.plist keys (PrimaryLanguage validity, missing keys, a CFBundleDisplayName clash with the app)
- the extension's product/module name "Keyboard" or the executable name
- APPLICATION_EXTENSION_API_ONLY
- an extension deployment target that differs from the app's
- device family
- an "Embed App Extensions" build phase in Debug vs Release
- extension sandbox profile requirements
- anything new in iOS 26 for keyboards

**Fix what you're confident about** (minimal changes in `ios/` only). Then write `agents/out/ios-keyboard-missing.md` with your ranked hypotheses, what you changed, and a concrete diagnostic to add to the CI simulator step that would confirm or refute each one. One example: check whether `Settings`' keyboard list in the simulator includes it, via `xcrun simctl spawn booted defaults read` or similar.
